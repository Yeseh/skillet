# Skillet — Domain Glossary

## Terms

- **Skill**: A folder containing a `SKILL.md` file (compiled output) and optionally scripts, references, and assets. Follows the [Agent Skills](https://agentskills.io/home) open format.
- **Skill source**: A `{name}.pan` file — the authoring format that compiles to `SKILL.md`. Contains template directives (fragment includes, typed refs, vars).
- **Fragment**: A reusable block of skill instructions. File named `{name}.fragment.pan`, lives in the workspace-global fragments directory. Included via `{> name <}` syntax. Block-level only, no parameters.
- **Ref**: A reference from a skill to an external entity. First-class concept with types: `ref::` (reference file), `cmd::` (CLI command), `skill::` (another skill in workspace), `var::` (workspace variable), `env::` (declared environment variable).
- **Reference name**: The value of a `ref::` directive — a reference file's path relative to the skill's `references/` directory, with the extension stripped. So `references/bla.md` is `ref::bla` and `references/docs/blo.md` is `ref::docs/blo`. Resolution is extension-agnostic across `.pan` and `.md`; a name that matches both extensions is a build error (ambiguous). At compile time `ref::name` is rewritten to the file's path relative to the skill (e.g. `` `references/docs/blo.md` ``).
- **Used reference**: A reference file is considered used when the owning skill's `.pan` source contains a `ref::` directive whose value matches the file's reference name (e.g. `ref::api/types` for `references/api/types.md`). Markdown links and cross-skill `ref::` paths do not count as usage. Enforced by the `unused-reference` lint rule.
- **Workspace**: A directory containing a `skillet.toml` and a skills directory. The unit of analysis for cross-skill operations (duplication detection, budget totals).
- **Plugin**: A named source/output pair declared in `skillet.toml` under `[plugin.(name)]`, with `src_dir`, `out_dir`, optional `fragments_dir`, `version`, optional `description`, and optional `publish` flag. All skill sources are declared as plugins. A plugin's `out_dir` is what gets distributed to agents as an agent plugin — `[workspace]` holds only global config (fragments, lint, build, vars, env).
- **Publish**: The act of emitting agent-ready marketplace manifests from the workspace. Triggered by `skillet publish`, which runs a build first (skippable with `--no-build`) then writes a `plugin.json` into each published plugin's `out_dir` and a `marketplace.json` into each agent-specific directory.
- **Published plugin**: A plugin with `publish = true` in its `[plugin.(name)]` block. Included in the generated marketplace as a plugin entry pointing to its `out_dir`.
- **Marketplace manifest**: The `marketplace.json` file generated by `skillet publish`. Written to `.claude-plugin/` for the `claude` agent and `.github/plugin/` for the `github-copilot` agent. Contains the marketplace name, owner, and an entry per published plugin.
- **Plugin manifest**: The `plugin.json` file generated into each published plugin's `out_dir`. Contains the plugin's `name`, `version`, and optional `description`. Required by agent plugin loaders to identify the plugin.
- **Budget**: The token cost of a skill measured in three tiers: discovery (description only, always loaded), activation (full SKILL.md), and transitive (activation + referenced files).
- **Discovery cost**: Tokens consumed by a skill's name + description at all times, even when the skill is not active.
- **Activation cost**: Tokens consumed when a skill is triggered — the full compiled SKILL.md.
- **Transitive cost**: Activation cost plus all files the skill instructs the agent to read.
- **Lockfile**: `skillet.lock` — committed workspace-level file recording source hashes, compiled hashes, token counts, fragment usage, and ref inventories per skill. Enables fast staleness checks and PR-diffable impact tracking.
- **SourceUnit**: A named piece of pre-read source content passed to the lib for compilation or analysis. Carries `name` and `content` (the raw `.pan` text) but no filesystem paths. The generic input type for skills, agent files, and any future compilable source type.
- **CompileContext**: The full bundle of data the lib needs to compile a single source unit: a `SourceUnit`, resolved fragment contents, and build config. Assembled by the CLI before calling into lib.
